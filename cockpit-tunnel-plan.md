# cockpit-tunnel

Status: plan (revised 2026-10-22). First-pass implementation written (not yet compiled; see `README.md`). Where the implementation intentionally deviates, this plan has been updated and the change is marked *(implementation)*. Private project, not open source.

Audience: implementers of the preview relay used by the custom app-building harness.

Adjacent cockpit work (different products): outbound WSS from sandboxes (`flycockpit/ws-sandboxy-proxy-plan.md`), cockpit session relay (`flycockpit/webrtc-relay-plan.md`).

## Goal

The harness builds apps for clients:

```text
user → harness web app → agent runtime --commands--> sandbox (no public IP, outbound 443 only)
```

A user asks the agent for a preview. The agent calls `generate_preview(port)`. The user then opens the app the agent is building in a new tab (or a harness iframe) and can exercise everything a real deployment would: HTTP, WebSockets, SSE/streaming, and WebRTC. Random internet users, scrapers, and link unfurlers must never reach a sandbox port.

**Agents must not have to write preview-specific code.** Everything that can be made transparent at the edge is made transparent.

## Decisions

| Topic | Decision |
|---|---|
| Language | Rust. Two binaries: `cockpit-tunnel-server` (VPS) and `cockpit-preview` (sandbox). |
| Reverse proxy | None. The server terminates TLS and proxies itself (axum + hyper + rustls). |
| TLS | One Let's Encrypt cert via DNS-01 covering `*.previews.example.com`, `tunnel.example.com`, `api.example.com`, `turn.example.com`. No per-host certs (rate limits, issuance latency, CT logs leak tunnel ids). |
| Database | SQLite (WAL) for tunnels, access links, gate sessions, ACME state. |
| UI | None. A bearer-token REST API is the only management surface. No user accounts, no 2FA. |
| Mux | Yamux over the outer WebSocket byte stream. |
| WebRTC | coturn from the distro package, ephemeral HMAC credentials, auto-injected into preview pages. No Docker/Podman. |
| Setup | `curl … \| sh` installs a verified binary, then `cockpit-tunnel-server setup` runs an interactive wizard. |

## Hostnames

All on one registrable domain so the harness dashboard can iframe previews same-site.

| Name | Role |
|---|---|
| `app.example.com` | Harness web app (iframe parent; not served by this project) |
| `api.example.com` | Management API (admin token) |
| `tunnel.example.com` | Sandbox control plane (WSS) |
| `{port}-{id}.previews.example.com` | Visitor hostnames, one per exposed port |
| `turn.example.com` | coturn (STUN/TURN; TURN-over-TLS reached via 443 SNI passthrough) |

`api` and `tunnel` may be the same host; keep them separate names so they can be split later. Do not submit `previews.example.com` to the Public Suffix List (that would make the iframe cross-site).

Same-site with untrusted preview code has consequences for `app.example.com` (owned by the harness, recorded here so it is not forgotten): its session cookies must be `__Host-`, and its CSRF defense must be tokens or `Origin` checks, never `SameSite`. Preview JS can set `Domain=example.com` cookies via `document.cookie`; the proxy cannot stop that.

## Credentials

| Credential | Minted by | Held by | Grants | Storage |
|---|---|---|---|---|
| Admin API token | setup wizard | harness backend only | Everything on `api.example.com` | SHA-256 hash in config |
| Tunnel token | `POST /v1/tunnels` | the sandbox (`COCKPIT_TUNNEL_TOKEN` env) | Connect as exactly one tunnel id; expose ports up to `max_ports` | SHA-256 hash in SQLite |
| Access link token | `POST /v1/tunnels/{id}/access-links` | one human, briefly | Create a gate session for that tunnel | SHA-256 hash in SQLite |
| Gate session | `/__access/{token}` | visitor browser (cookie) | View tunnels the session was granted | random id, SQLite + in-memory cache |
| TURN credential | edge / control channel | browser page, sandbox peer | Relay through coturn until expiry | stateless HMAC |

All tokens are ≥128-bit random, base64url, prefixed for secret scanners (`ctadm_`, `cttun_`, `ctacc_`). High-entropy tokens are hashed with SHA-256, not a password KDF.

Hard rules:

- The admin token never enters a sandbox. `generate_preview` runs in the agent runtime, not inside the sandbox.
- The tunnel token is passed by environment, never argv (argv is visible in `ps`).
- The agent never sees an access link. Agent transcripts are logged and echoed; the harness web app mints links on the user's click.

Secrets generated by setup: admin API token (printed once), ACME account key, coturn `static-auth-secret`. User-supplied: DNS provider API token. Config at `/etc/cockpit-tunnel/config.toml` (0600, owned by the `cockpit-tunnel` service user); data at `/var/lib/cockpit-tunnel/`. Gate sessions are opaque ids looked up server-side, so no cookie-signing key exists.

## End-to-end flow

```text
1. User: "show me a preview"
2. Agent → generate_preview(3000)
3. Agent runtime → POST https://api.example.com/v1/tunnels           (admin token)
   ← { id: "ab12cd", tunnel_token: "cttun_…", host_template: "{port}-ab12cd.previews.example.com" }
   (reused if this sandbox already has a live tunnel)
4. Agent runtime → sandbox: COCKPIT_TUNNEL_TOKEN=… cockpit-preview expose 3000
5. Agent runtime polls GET /v1/tunnels/ab12cd until port 3000 is connected
6. Tool result to agent: public hostname, connection status, WebRTC/env notes. No access link.
7. Harness web app shows "Open preview"
8. On click: web app → POST /v1/tunnels/ab12cd/access-links { ttl_s: 120, single_use: true }
   → window.open("https://3000-ab12cd.previews.example.com/__access/ctacc_…")
9. Edge validates token, creates/extends gate session, sets cookie, 302 → /
```

Click-time single-use links are never pasted anywhere, so unfurlers and mail scanners cannot burn them. For "share with my client" the API also mints reusable links (`single_use: false`, longer TTL, revocable, labeled).

## Management API

Bearer `ctadm_…` on `api.example.com`. JSON. OpenAPI generated with `utoipa`; the harness uses a generated typed client.

| Method | Path | Body / result |
|---|---|---|
| `POST` | `/v1/tunnels` | `{ label?, ttl_s, max_ports (default 8), host_header?: "rewrite" \| "preserve", inject_ice?: bool (default true), metadata? }` → `{ id, tunnel_token, host_template, expires_at }`. Token returned once. |
| `GET` | `/v1/tunnels` | List with status. |
| `GET` | `/v1/tunnels/{id}` | `{ id, connected, ports: [{ port, host, connected }], last_seen_at, expires_at, … }` |
| `PATCH` | `/v1/tunnels/{id}` | Extend TTL, change label/options. |
| `DELETE` | `/v1/tunnels/{id}` | Stop: in one transaction, hard-delete the tunnel row, its token hash, its access links, and its grants in every gate session (sessions left with no grants are deleted), and insert a tombstone. Then send a close on the control stream and drop the connection. Idempotent: deleting a tombstoned id returns `204`. |
| `POST` | `/v1/tunnels/{id}/access-links` | `{ ttl_s, single_use, label?, session_ttl_s? }` → `{ id, url_path: "/__access/ctacc_…", expires_at }`. Valid on any `{port}-{id}` host. |
| `DELETE` | `/v1/access-links/{id}` | Revoke link and gate sessions it created. |
| `POST` | `/v1/tunnels/{id}/turn-credentials` | `{ ttl_s }` → `{ iceServers, expires_at }` (for harness-side use; pages and sandbox get theirs automatically). |
| `GET` | `/healthz` | Unauthenticated liveness. |
| `GET` | `/v1/openapi.json` | The OpenAPI document (admin token). |

Errors: `401` bad token, `404` unknown id, `409` tunnel expired, `422` validation. Tunnel ids are 10 random lowercase base32 chars (unpredictable, DNS-safe).

*(implementation)* Creates (`POST /v1/tunnels`, `POST …/access-links`) return `201`. Error bodies are `{"error":{"code","message"}}`. `PATCH`, access-link creation, and turn-credentials return `409` for an expired *or tombstoned* tunnel (extending an expired tunnel would revive a revoked one); `GET` on a tombstoned id is `404`. `TunnelView` also carries `expired`, `created_at`, `host_template`, and `connected_since`. `label` ≤ 200 chars, `metadata` ≤ 16 KiB. The turn-credentials body is optional.

## Tunnel lifecycle

A tunnel is a row in SQLite, independent of any connection.

| State | Visitor sees on `{port}-{id}` |
|---|---|
| `active`, port connected | Proxied app |
| `active`, client disconnected or port not exposed | 502 "Preview offline" page (auto-retries every 5s). Never forwarded anywhere else. |
| `expired` / deleted (tombstone present) | 410 "Preview ended" |
| unknown id (never existed, or tombstone purged) | 404 |

- Reconnects reuse the same token and id, so links and gate sessions survive network blips.
- One control connection per tunnel. A new authenticated connection replaces the old one (handles half-open TCP); in-flight streams on the old one are dropped.
- Only ports the client declared are routable. A request for an undeclared port on a live tunnel gets the offline page, never a connection attempt to that sandbox port.
- TTL expiry and `DELETE` are the only revocation paths. Disconnect is not revocation, and neither is `unexpose` of the last port.
- When the agent stops a preview, the harness calls `DELETE /v1/tunnels/{id}` and the daemon exits on the server's close (`status --json` → `revoked`).
- Deletion keeps only a tombstone `(id, deleted_at)`: no token, labels, metadata, or links. Tombstones make old links show 410 and guarantee an id is never re-minted (id generation checks live tunnels and tombstones).
- An hourly purge job converts TTL-expired tunnels to tombstones (same cascade as `DELETE`), and removes tombstones older than 30 days, expired access links, and expired gate sessions.

## Sandbox client: `cockpit-preview`

Single static binary (musl on Linux; macOS and Windows builds optional).

```sh
COCKPIT_TUNNEL_TOKEN=cttun_… cockpit-preview expose 3000      # starts daemon if needed, adds port
cockpit-preview expose 8080                                    # adds a port to the running daemon
cockpit-preview unexpose 8080
cockpit-preview status --json
cockpit-preview ice --format env|json|file [--fresh]           # current ICE config for server-side peers
cockpit-preview ice --exec -- npm run dev                       # run a command with TURN_*/ICE_* set
cockpit-preview stop                                            # stop the daemon and forget its ports
```

- The first `expose` starts a background daemon; later commands talk to it over a Unix socket. *(implementation)* All client state lives in one 0700 directory, `$XDG_RUNTIME_DIR/cockpit-preview/` (fallback `/tmp/cockpit-preview-$UID/`, refused if owned by another user): `daemon.sock` (0600), `daemon.lock` (flock: one daemon per directory), `state.json` (0600, holds the token), `daemon.log`. One daemon, one control connection, many ports.
- Server URL from `COCKPIT_TUNNEL_SERVER` (default baked in at build time for the private deployment).
- Dials `wss://tunnel.example.com/v1/connect`, authenticates with the tunnel token, declares ports.
- Automatic reconnect: on any transport loss (network blip, missed pongs, VPS restart, server replacing the connection), retry forever with jittered exponential backoff (1s → 30s cap, reset after 60s connected), re-declaring all exposed ports. The only terminal outcomes are server responses `401` (token invalid) or `410` (tunnel expired/deleted): the daemon then exits with a distinct status (`status --json` reports `"state": "revoked"`, exit code 3), so the agent runtime knows to create a new tunnel. *(implementation)* A server `Close { Replaced }` (another client authenticated with the same token) is also terminal for this daemon: state `replaced`, exit code 4, and later commands do not restart it unless an explicit `expose` (or a different token) takes the tunnel back, so two sandboxes never fight over one token. With no daemon and no saved tunnel, `status` reports `stopped`.
- Daemon survival: exposed ports are persisted in a state file next to the socket. If the daemon is gone, any `cockpit-preview` subcommand restarts it from that state (same token from env or state file, mode 0600), so a crash or OOM kill heals on the next command. *(implementation)* `cockpit-preview stop` deletes the state and ICE files so nothing resurrects the daemon; SIGTERM keeps the state, so a killed daemon still heals.
- Local origin: connects to `127.0.0.1:{port}`, falling back to `[::1]:{port}` (Node ≥17 dev servers often bind `localhost` → `::1` only). Never connects to non-loopback addresses.
- WebRTC support: fetches TURN credentials over the control channel and maintains `$COCKPIT_ICE_FILE` (default `/run/cockpit-preview/ice.json`, else `$XDG_RUNTIME_DIR`), rewriting it atomically (write + rename) when less than 25% of the TTL remains. Also serves the same JSON at `http://127.0.0.1:{COCKPIT_ICE_PORT}/ice` (default 47801). *(implementation)* That endpoint rejects any `Host` other than `127.0.0.1`/`localhost` (DNS-rebinding guard), and the ICE file is deleted when the tunnel is revoked.
- Logs to stderr; `status --json` reports per-port connected state for the agent runtime.

## Control plane

1. Client dials WSS; disable outer `permessage-deflate`.
2. Wrap the WebSocket as a byte stream (reads concatenate binary frames; each write is one binary message).
3. Run Yamux on it. The server opens one stream per public HTTP request or WebSocket; the client never needs inbound connectivity.
4. Stream preamble: target port (u16, big-endian); the client answers with one status byte (`ok`, `refused` = nothing listening, `not exposed`). *(implementation: no flags field.)* The client connects to the local origin and splices bytes. HTTP is spoken end-to-end between the server's proxy and the origin; the client is a dumb byte pipe per stream.
5. A dedicated control stream carries: hello/auth, port declarations, TURN credential requests, server-initiated close.
6. Keepalive: WebSocket ping every 25s; drop after 2 missed pongs.
7. Flow control: Yamux per-stream windows (256 KiB) so one slow visitor or big upload cannot starve other streams. Max frame on the outer socket 512 KiB.

No nested RFC 6455: application WebSockets are raw bytes on a Yamux stream after the HTTP/1.1 `101`.

## Edge proxy

Visitor-facing on `*.previews.example.com`, HTTP/1.1 and HTTP/2 (ALPN). Toward the origin, always HTTP/1.1 over the Yamux stream.

Request handling order:

1. Parse `Host` as `{port}-{id}`; malformed → 404. *(implementation)* Routing is by `Host` only, never SNI: HTTP/2 clients may legitimately coalesce connections across names the wildcard certificate covers.
2. Tunnel state check (lifecycle table). *(implementation: before the gate, so a visitor without a session can tell an ended tunnel (410) from an unknown one (404); neither reveals anything about the app. `/__access/*` is handled before this check, so a link for an unknown, deleted, or expired tunnel gets the generic 401.)*
3. Reserved paths (`/__access/*`, `/__cockpit/*`) are handled at the edge and never forwarded.
4. Gate check (below). Failure → 401 page; the origin is never contacted.
5. Strip the gate cookie from `Cookie`. Strip client-supplied `X-Forwarded-*` / `Forwarded`, then set `X-Forwarded-Proto: https`, `X-Forwarded-Host: <public host>`, `X-Forwarded-For`.
6. Host header (per-tunnel `host_header`):
   - `rewrite` (default): send `Host: localhost:{port}`. Dev servers (Vite `allowedHosts`, webpack "Invalid Host header", Next dev origin checks) accept it without config. Rewrite response `Location` headers that point at `localhost:{port}` / `127.0.0.1:{port}` / `[::1]:{port}` to the public host.
   - `preserve`: send the public host. For apps that build absolute URLs from `Host` and ignore `X-Forwarded-Host`.
7. WebSocket: translate HTTP/2 Extended CONNECT (RFC 8441) to HTTP/1.1 `Upgrade`; re-add hop-by-hop `Upgrade`/`Connection`; after `101`, splice.
8. Stream responses write-through: no buffering, no added `Content-Length`, no compression added by the edge, flush per chunk.

*(implementation)* Also: `Expect`, `X-Real-IP`, and `Forwarded` are removed toward the origin; only WebSocket upgrades are forwarded (any other `Upgrade` is dropped as hop-by-hop); an Extended CONNECT the origin answers with a non-101 2xx becomes 502; opening the Yamux stream plus the client's status byte is bounded by 10s (timeout → offline page). In `rewrite` mode, same-tunnel `Origin`/`Referer` are mapped to `http://localhost:{port}`. `Location` and `Access-Control-Allow-Origin` rewriting (local origin → public host, and `http://` → `https://` for this tunnel's own hosts) applies in both host-header modes.

Response handling:

- `Set-Cookie`: pass through, preserving multiples. Strip any `Domain` attribute (`localhost`, `127.0.0.1`, or any parent of the preview host such as `.example.com` / `.previews.example.com`) so origin cookies become host-only on the public name. Drop any origin cookie named like the gate cookie.
- Iframe rewrites (always on, allowlisted parent `https://app.example.com`): remove `X-Frame-Options`; merge `frame-ancestors 'self' https://app.example.com` into an existing CSP (never strip CSP wholesale); rewrite `Cross-Origin-Resource-Policy: same-origin` to `same-site`.
- HTML injection (below).

Absolute `localhost` URLs baked into JS bundles are not rewritten.

## Visitor gate

Cookie:

```text
Set-Cookie: __Secure-cockpit-gate=<session id>; Domain=previews.example.com; Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=<session_ttl>
```

A parent-domain cookie, so one session covers every port of a tunnel (cross-port `fetch`/EventSource/WebSocket with credentials work) and ports exposed later need no new link. It carries only an opaque id; the session row lists granted tunnel ids.

Why this is acceptable on a shared parent:

- `HttpOnly`: preview JS cannot read it. It is stripped before every origin request, so no app ever sees it.
- Preview JS can *toss* a same-named non-HttpOnly cookie. The gate considers every `__Secure-cockpit-gate` value the browser sends and accepts the request if any value is a valid session granting this tunnel. Tossing can at worst add a useless value; it cannot grant access to another tunnel (grants are server-side).

`/__access/{token}`:

1. Look up the hash. Unknown, expired, revoked, or already-used single-use → 401 page (generic; no reason disclosed).
2. If the request carries a valid gate session, add the tunnel grant to it; else create a session. *(implementation: always mint a fresh session holding the new grant plus copies of the unexpired grants of every valid presented session, and set the cookie to it. A presented value may be one preview JS tossed (e.g. the attacker's own session id on a longer `Path`), so a grant is never attached to a session the client presents. Copying is harmless: tossing could already give the browser those grants.)*
3. Mark single-use links consumed (in the same SQLite transaction as the grant).
4. Set the cookie; `302` to `/` on the same host. The token never appears in a later URL.

Gate rules:

- No valid grant → 401 page. Never fetch the origin on failure.
- CORS preflight exception: an `OPTIONS` request with `Access-Control-Request-Method` and an `Origin` that is another `{port}-{id}` host of the *same* tunnel is forwarded without a cookie (preflights never carry cookies). Any other unauthenticated `OPTIONS` → 401.
- WebSocket and EventSource handshakes use the same cookie check.
- Session TTL defaults to 12h, capped by the tunnel's expiry. *(implementation: the cap is enforced live at the edge (an expired tunnel is 410), not stored on the grant, so a `PATCH` that extends the tunnel keeps visitors signed in.)*
- *(implementation)* Revoking a link (`DELETE /v1/access-links/{id}`) deletes every grant it contributed to, including grants carried into later sessions. Routine link expiry never deletes grants: an expired link is purged only once no live grant came from it.
- *(implementation)* Origin `Clear-Site-Data` loses its `"cookies"` and `"*"` directives (they would clear the gate cookie and the harness app's cookies across the registrable domain). Forwarded preflights carry no body and only CORS-relevant headers.
- Rate-limit `/__access/*` per IP (cheap insurance; tokens are 128-bit).

## Iframe

New tab is the compatibility guarantee; iframe is a same-site enhancement.

- Harness sets `frame-src https://*.previews.example.com` and iframes the access-link URL (or the bare host if the browser already has a session).
- Iframe attributes: no `sandbox` (or include `allow-same-origin allow-scripts allow-forms allow-popups`), `allow="camera; microphone; display-capture; fullscreen; clipboard-read; clipboard-write; autoplay"`.
- Known failures inside the iframe: IdP login pages (`X-Frame-Options: DENY`) — open in a new tab; cross-site parents; `credentialless` iframes. Not v1.

## WebRTC

### coturn

Installed from the distro package by setup when WebRTC is enabled, managed by systemd, config generated by setup:

```text

tls-listening-port=5349           # bound to 127.0.0.1; reached only via 443 SNI passthrough
listening-ip=<public ip>          # plus 127.0.0.1 for the TLS listener
external-ip=<public ip>
realm=turn.example.com
use-auth-secret
static-auth-secret=<generated>
cert=/var/lib/cockpit-tunnel/certs/fullchain.pem
pkey=/var/lib/cockpit-tunnel/certs/privkey.pem
min-port=49160
max-port=49999
no-multicast-peers
no-cli
denied-peer-ip=0.0.0.0-0.255.255.255
denied-peer-ip=10.0.0.0-10.255.255.255
denied-peer-ip=100.64.0.0-100.127.255.255
denied-peer-ip=127.0.0.0-127.255.255.255
denied-peer-ip=169.254.0.0-169.254.255.255
denied-peer-ip=172.16.0.0-172.31.255.255
denied-peer-ip=192.168.0.0-192.168.255.255
denied-peer-ip=fc00::-fdff:ffff:ffff:ffff:ffff:ffff:ffff:ffff
denied-peer-ip=fe80::-febf:ffff:ffff:ffff:ffff:ffff:ffff:ffff
denied-peer-ip=::1
denied-peer-ip=<public ip>
user-quota=12
total-quota=1200
max-bps=3000000
```

Firewall: open `3478/udp`, `3478/tcp`, `49160-49999/udp`; keep 5349 closed. On certificate renewal coturn is restarted (`systemctl try-restart coturn`). *(implementation)* The unprivileged server cannot do that itself, so setup installs a systemd path unit (`cockpit-tunnel-cert.path`) watching `fullchain.pem` that runs the restart as root.

*(implementation)* On 1:1 NAT hosts (most clouds) the public IPv4 is not on any interface, so binding it fails: coturn then listens on the default route's private address and advertises `external-ip=<public>/<private>`. coturn listens on IPv4 only. The config also sets `no-dtls` and `syslog`, starts with a "managed by setup" marker, and coturn is disabled again only if that marker is present when WebRTC is turned off. The coturn user joins the `cockpit-tunnel` group to read the 0640 cert/key.

### 443 SNI passthrough

Sandboxes can only reach outbound 443, and the Rust server owns 443. The listener peeks at the ClientHello: SNI `turn.example.com` → raw TCP splice to `127.0.0.1:5349`; everything else → normal TLS termination. Spike item: confirm Chrome, Firefox, Safari, and common server-side stacks (libwebrtc, Pion, aiortc) send SNI on `turns:`. If any do not, a ClientHello with no SNI also routes to coturn. *(implementation)* `webrtc.passthrough_no_sni` (default true) does exactly that. The peek is skipped entirely when WebRTC is disabled. Only the first TLS record is parsed; a ClientHello whose `server_name` lies beyond the first record counts as no SNI.

### Ephemeral credentials

Standard TURN REST scheme: `username = "<unix expiry>:<tunnel id>:<subject>"`, `credential = base64(HMAC-SHA1(static-auth-secret, username))`. `subject` is the gate session id prefix (browser) or `sbx` (sandbox) for coturn log attribution. Default TTL 1h for browsers, 24h for sandbox credentials (file, env snapshot, `ice` subcommand). Credentials cannot be revoked early; short TTL plus quotas is the containment. Deleting a tunnel stops new issuance immediately.

ICE server list returned everywhere:

```json
{
  "iceServers": [
    { "urls": "stun:turn.example.com:3478" },
    { "urls": ["turn:turn.example.com:3478?transport=udp",
               "turn:turn.example.com:3478?transport=tcp",
               "turns:turn.example.com:443?transport=tcp"],
      "username": "1761200000:ab12cd:v7f3a1",
      "credential": "…" }
  ],
  "expires_at": 1761200000
}
```

`GET /__cockpit/ice` on any preview host returns this for the current gate session (401 without one; never forwarded to the origin).

### Browser peers: zero app code (HTML injection)

When `inject_ice` is on (default) and a response is a navigation (`Sec-Fetch-Dest: document` or `iframe`) with `Content-Type: text/html`, the edge injects one inline script as the first child of `<head>` (or at document start if there is no `<head>`), using streaming rewriting. *(implementation)* A small hand-rolled streaming injector replaces `lol_html`: it buffers at most 16 KiB looking for `<head …>` (skipping comments, doctype, quoted attributes; `<header>` is not `<head>`), falls back to after `<html …>` / doctype, and passes everything after the insertion point through untouched. Empty bodies stay empty.

The script:

1. Inlines a freshly minted ICE list, so it is available synchronously at `new RTCPeerConnection()`.
2. Replaces `window.RTCPeerConnection` with a subclass whose constructor and `setConfiguration` **append** the cockpit servers to whatever `iceServers` the app passed (or use them alone if none). Subclassing keeps `instanceof`, the prototype, and static `generateCertificate()` intact. Idempotent if injected twice.
3. Refreshes from `/__cockpit/ice` in the background when less than 25% of the TTL remains (so long-lived tabs and service-worker-cached HTML get fresh credentials).

Edge requirements:

- For document requests, remove `Accept-Encoding` toward the origin so the HTML arrives uncompressed; the edge may compress the rewritten output.
- Drop `Content-Length` on rewritten responses (chunked/streamed).
- If the origin CSP has `script-src` (or `default-src`) without `'unsafe-inline'`, add the script's `'sha256-…'` hash (or a per-response nonce) to it. Never otherwise weaken CSP. *(implementation)* Hash only. A source list with `'unsafe-inline'` plus any nonce/hash/`'strict-dynamic'` does not allow all inline scripts (CSP3), so it gets the hash too; `'none'` is replaced by the hash; `default-src`-only policies get an explicit `script-src` copy plus the hash. `Content-Security-Policy-Report-Only` is untouched. A strict `connect-src` can block the background refresh `fetch`; that is not changed (the script retries every 60s).
- *(implementation)* Injection happens only for requests that passed the gate (never for preflights).
- Do not inject into non-navigation HTML (`fetch()`, htmx fragments) or into non-HTML responses.
- `inject_ice: false` per tunnel is the escape hatch.

### Sandbox peers: environment

The proxy cannot inject into Node/Python processes. A server-side peer (SFU, aiortc, Pion, voice agent) needs TURN-over-TLS on 443 because the sandbox has no UDP egress, and must read config. The agent runtime exports into the sandbox's agent shell environment, so every process the agent starts inherits it:

| Variable | Value |
|---|---|
| `COCKPIT_ICE_FILE` | Path the daemon keeps fresh (preferred for long-running processes) |
| `COCKPIT_ICE_URL` | `http://127.0.0.1:47801/ice` |
| `COCKPIT_ICE_SERVERS` | JSON snapshot valid ≥24h, written when `generate_preview` runs (convenience for short-lived processes) |
| `COCKPIT_PREVIEW_HOST_TEMPLATE` | `{port}-ab12cd.previews.example.com` |

`cockpit-preview ice --format env` prints shell exports of the current credential (`TURN_URLS`, `TURN_USERNAME`, `TURN_CREDENTIAL`, `ICE_SERVERS_JSON`, `ICE_EXPIRES_AT`) so the agent can restart a dev server with them. *(implementation)* `eval "$(…)" npm run dev` on one line does not work (`eval` joins its arguments into one string), so the client offers `cockpit-preview ice --exec -- npm run dev` (execs the command with the variables set) and documents `eval "$(cockpit-preview ice --format env)"; npm run dev`. `--format env` also exports `COCKPIT_ICE_FILE`. Values loaded at process start expire with the sandbox TTL (24h); long-running peers should re-read `COCKPIT_ICE_FILE`. Browser-only apps need nothing.

### Harness integration (informative; implemented in the harness, not this repo)

`generate_preview(port)` returns to the agent:

```json
{
  "url": "https://3000-ab12cd.previews.example.com",
  "host": "3000-ab12cd.previews.example.com",
  "status": "connected",
  "webrtc": {
    "browser": "Automatic. Do not add TURN config to browser code.",
    "server_side_peer": "Restart with: cockpit-preview ice --exec -- <dev command>. Long-running peers re-read $COCKPIT_ICE_FILE.",
    "ice_file": "/run/cockpit-preview/ice.json"
  },
  "rules": "Never write TURN credentials or preview hostnames into source files or committed .env files."
}
```

It deliberately returns no literal TURN credentials (they expire, and agents persist values they are handed into client code) and no access link (the web app mints those on click). The `url` is not usable without a gate session, so it is safe in transcripts.

### What needs app code

| Feature | App code |
|---|---|
| HTTP, streaming, SSE | None |
| WebSockets | None, provided URLs derive from `location` (the default for agent-written code) |
| WebRTC browser ↔ browser | None (injection) |
| WebRTC browser ↔ sandbox peer | Read `COCKPIT_ICE_*` in the server-side peer |

## Setup

```sh
curl -fsSL https://<private-host>/install.sh | sh
```

`install.sh` is thin: detect arch, download `cockpit-tunnel-server`, verify its checksum and minisign signature, install to `/usr/local/bin`, then `exec cockpit-tunnel-server setup </dev/tty`. All logic lives in the Rust wizard, which is versioned and testable.

Supported OS for v1: Debian 12+, Ubuntu 22.04+ (apt); Fedora 40+, RHEL/Alma/Rocky 9+ (dnf).

Wizard steps (each idempotent; re-running `setup` resumes or reconfigures). *(implementation)* Order is 1, 2, 4, 5, 3, 6, 7, 8, 9, 10, 11: the service user, directories, secrets, and `config.toml` are written before DNS, so answers survive a DNS timeout; if setup fails after a new admin token was saved, the token is printed on the error path (still only once). `--skip-dns` and `--skip-self-test` exist. A Let's Encrypt staging certificate left over when `--staging` is not given is reissued. The DNS check and self-test use a random never-queried preview name (and AAAA when IPv6 exists) so a cached NXDOMAIN cannot interfere. Stale AAAA records are reported, not deleted.

1. Ask: base domain, preview zone (default `previews.<base>`), API/tunnel/TURN hostnames, ACME contact email, DNS provider (Cloudflare, Hetzner, DigitalOcean, Route53) + scoped API token, enable WebRTC (y/N).
2. Detect the public IPv4/IPv6.
3. Create DNS records via the provider API: wildcard A/AAAA for the preview zone, A/AAAA for api/tunnel/turn. Verify they resolve to this VM from a public resolver before continuing.
4. Create the `cockpit-tunnel` system user, `/etc/cockpit-tunnel/`, `/var/lib/cockpit-tunnel/`.
5. Generate secrets (admin token, ACME account key, TURN secret). Store hashes or 0600 files.
6. Issue the certificate via DNS-01 (`instant-acme` + provider adapter). Offer `--staging` for testing.
7. If WebRTC: install coturn via the package manager, write its config, enable it.
8. Configure the firewall (ufw or firewalld if active): 80/tcp, 443/tcp, plus TURN ports if enabled.
9. Install and start the systemd unit (`AmbientCapabilities=CAP_NET_BIND_SERVICE`, `NoNewPrivileges`, `ProtectSystem=strict`, `ReadWritePaths=/var/lib/cockpit-tunnel`).
10. Self-test: `GET https://api.<base>/healthz`, and a TLS handshake on a random preview hostname.
11. Print the admin API token **once**, plus the harness env snippet (`COCKPIT_TUNNEL_API`, `COCKPIT_TUNNEL_ADMIN_TOKEN`).

Admin subcommands: `cockpit-tunnel-server token rotate`, `… status`, `… backup <path>` (`VACUUM INTO`), `… cert renew --force`.

Certificates: stored in `/var/lib/cockpit-tunnel/certs/`, loaded through a rustls `ResolvesServerCert` that swaps atomically on renewal (no restart). Renewal task uses ARI when offered, else renews when one third of the lifetime remains; do not hardcode 90 days. *(implementation)* instant-acme 0.7 has no ARI, so only the one-third rule is implemented (checked 60s after start, then every 12h, hourly after a failure). `acme-account.json` stores `{directory, credentials}`; toggling staging registers a new account. Public-resolver TXT confirmation is only a hint (Let's Encrypt queries the authoritative servers): a timeout logs a warning and issuance proceeds. Port 80 serves only a redirect to HTTPS.

## Observability

- Metrics (Prometheus text on `127.0.0.1:9464`): connected tunnels, live streams, bytes in/out per tunnel, gate denials, access-link redemptions, cert expiry.
- Logs: request line, host, status, duration, tunnel id. Never bodies, `Cookie`, `Authorization`, or tokens. *(implementation)* The query string is never logged and `/__access/*` paths are logged as `/__access/[redacted]`. WebSocket byte counts are added to metrics when the splice ends.

## v1 claims

- HTTPS previews of sandbox ports from a 443-outbound-only sandbox.
- Application WebSockets, SSE, chunked streaming, streamed uploads.
- N ports per tunnel, one control connection, new ports exposable at runtime.
- Click-time single-use and reusable access links → one gate session covering all of a tunnel's ports.
- Same-site harness iframe.
- WebRTC for browser peers with zero app code; for sandbox peers via `COCKPIT_ICE_*`.
- Links survive reconnects; revocation by `DELETE` or TTL.

## Not claimed

- Native gRPC, HTTP/2 trailers to origin, HTTP/3, WebTransport.
- Rewriting absolute URLs inside JS bundles.
- Cross-site iframe parents; IdP login inside the iframe.
- UDP tunneling of arbitrary sandbox ports (TURN is the WebRTC path).
- Early revocation of issued TURN credentials.
- A CDN in front of the VPS (buffers SSE).
- Custom per-client domains.

## Implementation sequence

1. **Mux spike.** Client dials WSS, server opens a Yamux stream, client returns `127.0.0.1:3000`. Prove reconnect, 25s ping, replace-on-reconnect.
2. **Edge.** Wildcard Host routing, HTTP/1.1 to origin, Upgrade splice, Extended CONNECT, write-through streaming, Host rewrite + `Location` fixup. Prove Vite (HMR + `allowedHosts`), Next dev, and an Express SSE endpoint.
3. **SQLite + API.** Tunnels, tokens, lifecycle states, OpenAPI.
4. **Gate.** Access links, sessions, cookie stripping, `Set-Cookie` Domain stripping, preflight exception, iframe header rewrites.
5. **Client daemon.** `expose`/`unexpose`/`status` over the Unix socket, `::1` fallback.
6. **TLS + setup.** DNS-01 with Cloudflare first, then the other providers; wizard; systemd; self-test.
7. **WebRTC.** coturn config, SNI passthrough spike, `/__cockpit/ice`, HTML injection, CSP hash merge, sandbox ICE file/URL.
8. **Hardening.** Rate limits, quotas, metrics, log redaction review.

## Tests required before done

Mechanically checkable; run against a real server process in CI with a local origin.

Proxy:
- GET HTML through the tunnel is byte-identical to the origin (injection disabled).
- WebSocket echo over HTTP/1.1 and over HTTP/2 Extended CONNECT.
- SSE: origin emits an event, sleeps 2s, emits another; client receives the first event before the origin's sleep ends.
- SSE with 10s of silence between events stays open.
- Chunked response without `Content-Length` arrives incrementally.
- 50 MB upload completes while server RSS stays below a fixed bound (streamed, not buffered).
- Vite dev server with default config serves through the tunnel and HMR reconnects after a file change.
- Origin `Location: http://localhost:3000/login` reaches the browser as `https://3000-{id}.previews…/login`.
- Request for an undeclared port returns the offline page and the client receives no stream.

Gate:
- No cookie → 401; origin request counter unchanged.
- Single-use link redeemed twice → second is 401.
- One access link on port 3000 grants port 8080 of the same tunnel, and not another tunnel.
- Cross-port preflight from `3000-{id}` to `8080-{id}` reaches the origin; preflight from another tunnel's host → 401.
- Origin `Set-Cookie: session=…` works; origin never receives `__Secure-cockpit-gate`.
- Origin `Set-Cookie: x=1; Domain=.example.com` reaches the browser without `Domain`.
- A tossed non-HttpOnly `__Secure-cockpit-gate=garbage` alongside a valid one still authenticates.
- `DELETE /v1/tunnels/{id}` → next request 410, control connection closed, access links 401.
- After `DELETE`, SQLite holds no row for the tunnel, its token, links, or grants except the tombstone; a second `DELETE` returns 204.
- Purge with the tombstone aged past 30 days → the tombstone is gone and the host returns 404.
- An expired tunnel is tombstoned by the purge job with the same cascade as `DELETE`.
- Disconnect client → 502 offline page; reconnect → same URL and cookie work again.
- Restart the server process while a client is connected → client reconnects without intervention and all previously exposed ports route again.
- Server rejects the token with 410 → daemon exits; `status --json` reports `revoked`; no further connection attempts.
- `kill -9` the daemon, then run `cockpit-preview status` → daemon restarts with the previously exposed ports.
- `cockpit-preview ice --format env` output, `eval`ed, yields a credential coturn accepts.

Iframe:
- Page with Helmet defaults loads in an iframe from `https://app.example.com`; its `script-src` is unchanged except for any injected hash.
- WebSocket from inside the iframe authenticates with the gate cookie.

WebRTC:
- `/__cockpit/ice` without a session → 401; with one → valid credential coturn accepts.
- Injected page: `new RTCPeerConnection()` with no config gathers a `relay` candidate.
- Injected page: `new RTCPeerConnection({iceServers:[{urls:"stun:stun.l.google.com:19302"}]})` keeps that server and adds cockpit's.
- `pc instanceof RTCPeerConnection` and `RTCPeerConnection.generateCertificate` still work after injection.
- Page with strict `script-src 'self'` runs the injected script (hash added) and still blocks other inline scripts.
- Sandbox peer using `COCKPIT_ICE_FILE` connects to a browser peer with only TCP 443 egress allowed.
- TURN relay to `127.0.0.1`, `169.254.169.254`, a private range, and the VM's public IP is refused.
- After an injected credential's TTL is forced short, a new `RTCPeerConnection` uses the refreshed one.

Setup:
- Re-running `setup` on a configured host changes nothing unless an answer changes.
- Admin token printed once; config contains only its hash.

## Open choices (do not block v1)

- Yamux vs agent-as-HTTP/2-server over the WebSocket (VPS as h2 client; built-in flow control; WebSocket via Extended CONNECT). Revisit only if the Yamux spike shows problems.

## Non-goals
